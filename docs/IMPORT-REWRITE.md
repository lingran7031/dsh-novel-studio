# 半成品导入与剧情改写（0.2.0）

0.2.0 把「拿一本半成品继续写」和「把已有剧情改掉」做成了独立工作流：导入批次、分析归档、改写方案、按章候选、对照审阅、整批采用与版本回退。

## 1. 适用场景

- 手上有 TXT / Markdown 半成品，想先归档人物、世界观、大纲与伏笔，再续写；
- 已写了几章，想统一改文风、修时间线或重写某些章节，但不想破坏原有资料；
- 想比较「原稿 vs 候选稿」，满意后整批替换，不满意随时回退。

## 2. 前置条件

- 当前会话必须是「小说工作室」预设；
- 分析 / 方案 / 改写动作通过当前会话的真实 Agent 派发，会话忙碌时会被拒绝；
- 原稿支持 `.txt` / `.md`，UTF-8 或 GB18030；单份上限 16 MiB；
- 首版不改变章节数量与顺序，不做自动增删、拆合、重排。

## 3. 操作步骤

1. **上传**：右栏写作台 →「导入改写」→ 选择 TXT / Markdown 文件，或粘贴原文。原始字节会保留，归一化另存。
2. **校对切章**：检查章节标题、正文和切分点；最后一章残缺可标记为半章。修改切章会让旧分析失效。
3. **分析原稿**：Lead 按分块读取原文，归档该导入批次的人物、规则、大纲、时间线、伏笔、关系、文风与逐章摘要。分析完成前不能采用为正式书稿，也不能创建改写。
4. **采用或改写**：可以把该批次采用为正式书稿；也可以填写改写要求、起止章节、保留项、禁止改动项、改写程度，生成改写方案。
5. **确认方案**：方案必须逐章说明保留、改写或联动检查；范围外章节不会被悄悄改写。
6. **顺序执行**：确认后按依赖顺序领取章节，逐章改写、审阅、更新候选资料；每章提交带版本与领取令牌校验。暂停后旧提交会被拒绝；恢复从最早未完成章节继续。
7. **对照与采用**：对照页展示原稿、候选正文、修改摘要与审阅意见；全稿资料与一致性验收通过后，才能整批采用为新正式版本。
8. **回退**：版本列表可恢复旧正式稿，回退会同时覆盖正文、资料、摘要与进度；回退前的当前修改会先保存为版本，导入证据与候选历史保留。

## 4. 存储结构

```
story/imports/<importId>/          # 原始字节、归一化原文、切章、分析与来源哈希
story/rewrites/<rewriteId>/        # 冻结原稿、改写要求、方案、队列、审阅、候选项目
story/versions/<versionId>/        # 正式稿与资料的完整受管快照
story/versions/index.json          # activeVersionId / currentHash / versions[]
story/versions/transaction.json    # 采用 / 回退事务日志（崩溃恢复）
```

- `story/imports/` 与 `story/rewrites/` 由插件管理，不建议手工修改；
- 每个正式版本都有 manifest 与文件哈希；采用和回退在同一把项目锁下执行；
- 事务中断后，下次访问会依据 `transaction.json` 自动恢复（提交完成或回滚到事务前）。

## 5. 接口

### GET

| 路径 | 说明 |
|---|---|
| `/novel-studio/api/workflow` | 批次、任务、版本列表、当前会话的派单能力 |
| `/novel-studio/api/import?importId=` | 导入批次切章 |
| `/novel-studio/api/compare?rewriteId=&chapter=` | 原稿 / 候选 / 修改摘要 / 审阅 |
| `/novel-studio/api/revision-library?rewriteId=&kind=original\|candidate` | 原稿或候选版资料库 |

### POST `/novel-studio/api/workflow`

请求体是 JSON 对象，`action` 决定操作：

| 分类 | action |
|---|---|
| 导入 | `import`、`save_chapters`、`materialize_import` |
| 分析 / 派发 | `analyze`、`plan`、`run`、`start`、`resume`、`retry` |
| 改写任务 | `create_rewrite`、`save_plan`、`approve_plan`、`pause`、`cancel` |
| 章节候选（模型侧） | `claim_chapter`、`save_candidate`、`save_materials`、`finalize` |
| 正式版本 | `apply`、`rollback` |

- 分析、方案、执行类动作需要 `sessionId`；
- 模型执行期间只写候选批次；正式采用与回退必须由用户确认；
- 请求要求同源 JSON（`content-type: application/json`，拒绝跨站）。

## 6. 限制与失败处理

- 章节数量与顺序不变；不支持自动增删、拆合或重排章节；
- 未完成分析的批次不能采用，也不能基于它创建改写；
- 原稿被修改（哈希不符）时拒绝生成对照，需重新导入或冻结；
- 会话忙碌、工作目录变化、预设不匹配时明确报错，不会假装已开始；
- 版本恢复会整体覆盖受管文件；未纳入受管范围的文件不会被动。

如果面板提示能力不可用：确认当前会话是「小说工作室」预设、工作目录仍是原项目目录、会话不在运行中，然后点重试。
