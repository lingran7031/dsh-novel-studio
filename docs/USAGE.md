# 使用指南

## 1. 安装

### 前置

- DeepSeek Harness Desktop 或 Web，支持 Agent Presets（团队协作还需要 Agent Teams）；
- Node.js ≥ 20；DSH 中已配置可用模型。

### 获取仓库

```powershell
git clone https://github.com/lingran7031/dsh-novel-studio.git
cd dsh-novel-studio
```

### 安装到 DSH profile

二选一：

**A. 插件管理器（推荐）**

在 DSH 的 Creator 模式会话中让 Agent 调用：

```text
plugin_manager → install_bundle → target = <克隆目录绝对路径>
```

**B. dsh CLI**

```powershell
dsh plugin --profile <profile> add "file:<克隆目录绝对路径>"
```

安装后刷新页面。若插件管理器提示重启，重启 DSH 一次。

### 验证安装

新建会话的 Agent 预设选择器里应出现 **小说工作室**；也可以用自检接口：

```powershell
curl.exe http://127.0.0.1:<port>/novel-studio/api/status
```

期望：`preset.broken` 为空、`composition.rows` 全部 `active`、`tools` 含 6 个 `novel_*`、
`novelToolsInStandard` 为空、`skills` 含 8 个 `novel-*`。

### 卸载

```text
plugin_manager → remove_bundle → dsh-novel-studio
```

## 2. 进入写作模式

新建会话 → 选择预设 **小说工作室** → 选择一个工作区（建议每本书一个独立目录）。
会话工作目录就是小说项目根目录；首次使用时 Lead 会帮你 `novel_project init`。

刷新页面后如果找不到入口：先尝试 `Ctrl+Shift+R` 硬刷新；仍没有就重启 DSH。

## 3. 新书：从想法到章节

**第一步：说明需求**

> 开一本都市悬疑：主角是法医，基调冷峻克制，目标 30 章。先给我前提、人物和 12 章大纲。

Lead 会问五个问题（题材基调、主角冲突、篇幅节奏、文风、禁忌），也可以让它先给默认值。

**第二步：确认蓝图**

架构师产出前提、人物、世界规则与卷/弧/章大纲；编辑做逻辑审阅，裁定者处理设定冲突；
Lead 汇总成「故事蓝图」请你确认。蓝图确认前不会正式开写。

**第三步：进入章节循环**

确认后说：

> 蓝图可以，开始写第 1 章。

每章：上下文包 → 章节计划 → 正文初稿 → 编辑审阅/打磨 →（争议时裁定）→ 定稿 → 资料归档 → 体检 → 简报。
蓝图、卷末、重大裁定、你叫停时暂停；其余自动推进。

## 4. 继续已有项目

打开包含小说项目的工作区，输入：

> 继续写第 N 章。
> 先体检一下资料库，再继续。
> 把第 7 章按编辑意见重审一遍。

Lead 会先读 `story/state.json`、`meta/progress.json` 与任务板，再从断点继续。

## 5. 半成品导入与剧情改写

0.2.0 的完整流程（见 [IMPORT-REWRITE.md](IMPORT-REWRITE.md)）：

1. 右栏「写作台」→「导入改写」→ 上传 TXT / Markdown（或粘贴原文）；
2. 校对切章，必要时调整标题、正文、分章；
3. 分析原稿并归档该批次资料；
4. 把该批次采用为正式书稿，或生成改写方案；
5. 按章节顺序改写、审阅、对照；
6. 面板确认整批采用；不满意可以在版本列表回退。

也可以直接用对话发起旧版导入：

> 分析 `source/半成品.txt`，按标准档归档后从断点续写。

## 6. 右栏写作台

打开：会话页右上角「展开右栏」→ 右栏顶部 `+` → 指南卡「写作台」。
详见 [PANEL.md](PANEL.md)。

- **概览**：书名、阶段、章节/已定稿、总字数、未回收伏笔、裁定数、最近章节、下一章。
- **章节**：阅读全文、搜索、上/下一章、字号、复制。
- **资料库**：13 类资料查看与搜索。
- **导入改写**：0.2.0 的导入、分析、方案、改写与版本入口。
- **快捷操作**：复制续写指令、导出 Markdown / DOCX。

## 7. 常用指令速查

| 想要 | 直接说 / 用 |
|---|---|
| 查进度 | `/novel-status` 或「看下现在写到哪了」 |
| 导出整本 | `/novel-export`、`/novel-export docx` |
| 准备某章上下文 | 「给第 8 章准备上下文」→ `novel_context` |
| 资料体检 | 「体检资料库」→ `novel_validate` |
| 重审某章 | 「让编辑复查第 3 章的一致性」 |
| 拍板争议 | 「作者和编辑对第 4 章结尾有分歧，让裁定者拍板」 |
| 路线选择 | 「列出三个续写方向，我来选」 |
| 改稿 | 「把第 5–7 章改成更克制的文风，先给方案」 |
| 回退 | 「恢复到上一个正式版本」 |

## 8. 写作技巧与成本控制

- 章节计划、正文、审阅都落盘，Lead 只读摘要与结论；不要让 Lead 通读全书。
- 一章一循环，卷末做一次全量 `novel_validate` 与方向复盘。
- 长项目用 `novel_context` 的有界上下文包；信息不足时让角色定向读文件，而不是整本载入。
- 重要设定变更走裁定记录：`story/decisions/` 里要有证据、结论、影响范围。
- 导入分析按档位选：快速（最近章节）／标准（逐章摘要 + 实体）／深度（逐章细读 + 交叉校验）。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 预设选择器没有「小说工作室」 | 刷新页面；仍没有就重启 DSH |
| 改了代码/技能不生效 | 插件管理器禁用→启用 bundle；必要时重启 |
| 右栏「开始」页空白 | 硬刷新页面；打开 DevTools Console 看 slot 报错 |
| 写作台提示「无法读取当前会话目录」 | 用已有工作区的会话打开；或从命令行 `?path=` 显式指定 |
| `novel_import` 编码/切章异常 | 仅 .txt/.md；UTF-8 / GB18030；扫描 PDF 先转文本 |
| 改写操作提示「请打开小说工作室会话」 | 只能在「小说工作室」预设的会话里运行改写 |
| 资料冲突多 | 先 `novel_validate`，再让 Editor 回查、Arbiter 逐条裁定 |

更多：见 [DEVELOPMENT.md](DEVELOPMENT.md) 的故障排查一节。
